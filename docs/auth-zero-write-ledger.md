# 鉴权零写说明（专册·钉死）

> 本册为解冻写路径鉴权的唯一口径，落册即锁定。**鉴权当天不得改口**，不得在甲/乙两套写法之间混用或切换。任何偏离本册的实现一律拒绝，并在审计中以 `鉴权偏了` 留痕。

## 一、路径选型（二选一，已钉死）

| 路径 | 写法 | 是否选用 |
|----|----|----|
| **甲** | 越权请求在**服务端**拦截并记审计，正式侧**零写入**（不改输出态、不写补采队列） | ✅ **选定并锁定** |
| 乙 | 先建解冻意图单，经值班确认后由服务端写入解冻态；未确认则到站正式保持未写入 | ❌ 不采用 |

- 代码锁定常量：`backend/app.py` 的 `AUTH_PATH_LOCKED = "甲"`。
- 甲乙两套写法**不得混用**：本实现不引入任何「意图单 / 待确认」表与流程；解冻只有「服务端当场鉴权 → 放行写或拦截零写」这一种写法。
- 选型当天禁止改册为乙；如确需变更，须另起变更评审，不在鉴权当天进行。

## 二、零写口径（甲路径硬约束）

1. **服务端强制，不靠前端**：前端隐藏按钮仅为体验，真正的鉴权在 `POST /api/catchup/{source}` 写路径入口判定。只藏入口判本关失败。
2. **只读令牌禁止改输出态**：角色为「只读」的会话调用解冻，一律 `403`，且：
   - `sources.output_mode` 保持原值（冻结仍是冻结）；
   - `catchups`（补采队列正式侧）不新增任何行；
   - 仅向 `auth_audit` 审计表追加一条 `result='越权拦截'` 记录。
3. **采集写路径同口径**：`POST /api/arrivals` 同样仅管理角色可写，只读令牌命中即 `403` + 审计，正式侧零写入。
4. **未登录**仍为 `401`，与越权 `403` 区分。
5. 任何试图绕过本说明（非管理角色触碰写路径、绕过锁）的请求，审计结果记为 `鉴权偏了`，请求拒绝。

## 三、鉴权锁与争用留痕

- 解冻写路径全程持有模块级鉴权锁 `UNFREEZE_LOCK`，把「鉴权判定 + 输出态更新 + 补采队列写入」串行化为一个临界区。
- 只读与管理两路**同时**打同一源解冻时：后到一路等锁；进锁后发现该源已有在先解冻（`inflight` 命中），其审计行 `contended=1`，即「后交只记鉴权解冻争用」。
- 管理路正常解冻并写一次正式侧；只读路即便后交也只留审计、正式侧零写入。锁不得被跳过。

## 四、口令与库文件落点

- **口令沿用本仓鉴权侧**：复用既有 `users` 表与会话签发（`/api/login` → Bearer 会话），不新开鉴权台、不另设口令体系。管理 `admin/123456`，只读 `viewer/view123`。
- **库文件放在鉴权仓区**：不另挂外置库，所有鉴权相关表（`auth_audit`、`auth_ledger`）与业务表同落在本仓 `data/app.db`（SQLite）。

## 五、权限五处对齐（验收须一致可读）

| # | 位置 | 对齐口径 |
|---|------|---------|
| 1 | 权限附页（时限台内「权限说明」页签，非新开鉴权台） | 展示锁定路径甲、当前角色、可写/只读边界，数据取自 `/api/auth-policy` |
| 2 | 审计列表（时限台内「审计列表」页签） | 读 `/api/audit`，呈现 actor/action/target/result/contended |
| 3 | 源目录（左侧及「滞后分级」页签） | 只读角色不渲染解冻/登记写按钮，管理角色才渲染；服务端同时强制 |
| 4 | 补采队列（「补齐记录」页签） | 每条记录显示 `operator`，越权不产生队列行 |
| 5 | 水位页（首页水位卡片） | 冻结/降级计数对只读与管理一致可读，只读不能借水位写库 |

五处对同一套角色与策略读数，只读与管理看到的**数据一致**，差异仅在写操作是否可用，且最终均由服务端裁决。
